01
Alapfogalmak

Felhőből Cloud Native

Virtuális gép vagy konténer?

A VM teljes vendég operációs rendszert futtat. A konténer a host kernelét használja, ezért kisebb és gyorsabban indul.

Image vagy container?

Az image sablon. A container az image futó példánya. Ugyanabból az image-ből több izolált példány indítható.

Miért registry?

A registry központi image-tároló. Az elkészített image más gépen vagy Kubernetes klaszteren is letölthető.

Miért Kubernetes?

Automatizálja a konténerek telepítését, skálázását, újraindítását és frissítését, és kívánt állapotot tart fenn.

1. modul • 45 perc

GitHub Codespaces – fejlesztés a felhőben

Tanulási cél: távoli Linux fejlesztői környezet létrehozása és webalkalmazás futtatása felhőben.
  1. Hozz létre cloud-native-labor nevű GitHub repositoryt.
  2. Töltsd fel a starter ZIP kicsomagolt tartalmát.
  3. Indíts Codespace-t: Code → Codespaces → Create codespace on main.
  4. Ellenőrizd a környezetet:
uname -a python --version git --version docker --version kubectl version --client

Indítsd el az alkalmazást és nyisd meg a 8080-as port előnézetét:

pip install -r requirements.txt python app.py
Ellenőrzés: a /health végpont {"status":"ok"} választ ad.
Bizonyíték 01–02: terminál a verziókkal; működő CloudLab oldal Codespaces port-előnézetben.
Gondolkodj: mi fut a saját gépeden és mi a GitHub infrastruktúráján?
2. modul • 45 perc

Docker alapok – image, container, port, log, lifecycle

Tanulási cél: container indítása, porttovábbítás, naplózás, leállítás és törlés.
docker pull nginx:alpine docker image ls docker run -d --name web1 -p 8081:80 nginx:alpine docker ps docker logs web1 curl http://127.0.0.1:8081 docker stop web1 docker rm web1
Mini kihívás: indíts két Nginx konténert web-a és web-b néven két külön host porton.
Ellenőrzés: a docker ps egyszerre két futó konténert mutat külön PORTS értékkel.
Bizonyíték 03–04: image lista; két egyszerre futó konténer.
3. modul • 45 perc

Dockerfile, Compose, volume és Docker Hub

Tanulási cél: saját image és többkonténeres alkalmazás készítése, tartós adattal.
docker build -t cloudlab:1.0 . docker image ls docker run -d --name cloudlab -p 8080:8080 cloudlab:1.0 curl http://127.0.0.1:8080/health

Compose: webalkalmazás + Redis.

docker rm -f cloudlab docker compose up -d --build docker compose ps docker compose logs --tail=30 curl http://127.0.0.1:8080/api/info

Frissítsd többször az oldalt. A számláló növekedjen. Ezután teszteld a volume tartósságát:

docker compose down docker compose up -d docker volume ls

Docker Hub:

docker login docker tag cloudlab:1.0 SAJAT_DOCKERHUB_NEV/cloudlab:1.0 docker push SAJAT_DOCKERHUB_NEV/cloudlab:1.0
Bizonyíték 05–07: saját image; működő Compose két szolgáltatással; Docker Hub 1.0 tag.
4. modul • 45 perc

Kubernetes alapok – Deployment és Service

Környezet: Killercoda Kubernetes labor vagy tanári klaszter.

A k8s.yaml fájlban cseréld ki a DOCKERHUB_FELHASZNALO részt.

kubectl apply -f k8s.yaml kubectl get deployments kubectl get pods -o wide kubectl get services kubectl describe deployment cloudlab

Port-forward:

kubectl port-forward service/cloudlab 8080:80
Ellenőrzés: 2 Running pod + cloudlab Service + működő /health.
Bizonyíték 08–09: podlista; Kubernetesből elérhető alkalmazás.
5. modul • 45 perc

Kubernetes üzemeltetés – skálázás, self-healing, rollout

Tanulási cél: megtapasztalni a Kubernetes kívántállapot-kezelését.
kubectl scale deployment cloudlab --replicas=4 kubectl get pods -w

Törölj egy podot és figyeld az automatikus pótlást:

kubectl get pods kubectl delete pod POD_NEVE kubectl get pods -w

Rollout ellenőrzés:

kubectl set image deployment/cloudlab cloudlab=SAJAT_DOCKERHUB_NEV/cloudlab:1.0 kubectl rollout status deployment/cloudlab kubectl rollout history deployment/cloudlab
Hibakeresés: hibás podnál használd a kubectl describe pod és kubectl logs parancsokat.
Bizonyíték 10–12: 4 replica; self-healing; rollout státusz.
6. modul • 45 perc

CI/CD – GitHub Actions és Cloudflare Pages

Tanulási cél: automatikus build/health-check és Git-alapú felhős publikálás.

A starterben lévő workflow push után Docker image-et buildel, konténert indít és health-checket futtat.

git add . git commit -m "CloudLab CI teszt" git push

GitHubon az Actions fülön ellenőrizd a sikeres futást.

Második felhőszolgáltató: Cloudflare Pages-ben kapcsold össze a repositoryt, és publikálj egy status.html oldalt a neveddel, GitHub és Docker Hub linkkel.
Bizonyíték 13–15: sikeres Actions futás; Cloudflare Pages deployment; publikus status oldal.
